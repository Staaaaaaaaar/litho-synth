# LithoSynth v1.0 方案

- 更新日期：2026-08-28

## 1. 项目定位

LithoSynth 是面向多岩石多样性研究的合成场景、数据生成与分析工具。

项目复用现有场景构建和渲染技术，生成具有已知岩石属性的可控数据，用于支持后续视觉表征等研究。LithoSynth 不以重新开发通用合成数据引擎或完整行星模拟器为目标。

## 2. 核心能力

LithoSynth 计划提供四类能力：

1. 多岩石场景构建与可重复随机生成；
2. RGB、深度、实例标注及相关属性的生成和导出；
3. 基于合成过程中已知属性的场景级、数据集级多样性分析；
4. 场景、属性分布和多样性结果的基础可视化。

基本流程：

```text
场景配置
  → 场景构建与渲染
  → 图像、标注和已知属性导出
  → 多样性分析
  → 可视化与结果检查
```

## 3. 功能边界

LithoSynth 当前不负责：

- 岩石检测、分割等感知算法；
- 视觉表征或 embedding 的设计与训练；
- 多样化采样、Top-K 选择和机器人决策；
- 机械狗、机械臂或采样过程仿真；
- 完整月球或火星物理模拟。

这些能力可以使用 LithoSynth 生成的数据，但不属于当前项目实现范围。

## 4. v0.1 技术路线

首个后端采用 BlenderProc，必要时使用 `bpy` 补充其未封装的场景操作。

v0.1 先完成最简单的可运行场景：

```text
平坦地形
+ 随机放置的多块岩石
+ 基础相机与光照
+ 可复现随机种子
+ 基础数据与属性导出
```

BlenderProc 主要负责场景编排、相机、渲染通道和标注输出；LithoSynth 负责配置组织、岩石属性记录、多样性分析和可视化。

## 5. 开发原则

- 先建立最小可运行闭环，再逐步提高场景复杂度和保真度；
- 优先复用、适配和集成已有工作；
- 第一阶段只实现一个后端，同时保留后续扩展边界；
- 不在文献和实验依据不足时提前固定数据结构、属性体系或多样性算法；
- 场景与数据功能应直接服务多岩石多样性研究。

## 6. 初步阶段

1. 建立项目与 BlenderProc 运行骨架；
2. 完成最小多岩石场景渲染；
3. 完成基础数据和已知属性导出；
4. 加入基础检查与可视化；
5. 在后续调研基础上确定多样性定义和分析方法；
6. 根据需要迁移或接入 LuNaSynth、OmniLRS 等已有工作。

## 7. 待确定事项

- 岩石资产来源和生成方式；
- 正式输出数据结构；
- 岩石属性范围；
- 多样性定义与评价方法；
- 后续行星地形、材质和其他后端的接入顺序。
